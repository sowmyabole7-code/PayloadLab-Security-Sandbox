The Inherent Limit of Regex Detection

Regex pattern matching is helpful for preliminary heuristic telemetry and Web Application Firewall (WAF) rule sets, but input filters cannot guarantee security. Attackers continuously bypass regex through encoding mutations, nested tags, and character set permutations. The authentic, non-bypassable defenses are Contextual Output Encoding for HTML and Parameterized Queries (Prepared Statements) for SQL.

Bypass Awareness: Why Naive Filters Fail

Common ways attackers bypass ad-hoc regex filters in web applications:

1. Nested Tag Stripping

A filter that deletes <script> once will turn <scr<script>ipt> right back into an active <script> tag after execution.

2. Multi-Decode Pitfalls

If an application sanitizes before URL-decoding, double-encoded payloads like %253Cscript%253E bypass the filter and execute upon decode.

3. Non-Whitespace Delimiters

In SQL, comments like /**/ or line breaks can replace spaces, dodging regexes written as \s+OR\s+.

4. Case & Encoding Mutations

HTML browsers tolerate mixed case (<sCrIpt>), missing quotes, and null-bytes that simple patterns overlook.
